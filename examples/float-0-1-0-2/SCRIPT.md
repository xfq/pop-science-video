# SCRIPT · 为什么 0.1 + 0.2 不等于 0.3

> 实测 100.5 秒，33 句旁白，34 条字幕。`tts` 是给配音读的文本，`caption` 是屏幕字幕；数字在字幕里保留阿拉伯数字，在配音里写读法。

## 1. 开场 · 真实输出（13.8s）

- `q`：如果我问你：0.1 加 0.2 等于多少？
- ：你大概会说：0.3 啊。
- `result`：但计算机给出的是 0.30000000000000004。
- `note`：这不是 bug。

## 2. 转折 · 不是 bug，是二进制（8.4s）

- `line1`：这不是 bug，也不是 Python 的锅。
- `line2`：是二进制。
- `sub`：换 JavaScript、C、Java，结果都一样。

## 3. 机制 · 0.1 是怎么变成近似值的（18.3s）

- `s0`：0.1 在二进制里无限循环。
- `s1`：一个 double 只留 53 位。
- `s2`：多出来的部分，舍入到最近的 53 位。
- `s3`：存进去的 0.1 已不再精确。
- `s4`：相加，再舍入一次。
- `foot`：误差从输入就开始了。

## 4. 编码 · 64 位怎么花（12.3s）

- `b0`：一个 double 占 64 位。
- `b1`：符号 1 位，指数 11 位，尾数 52 位。
- `b2`：尾数前面隐含一个 1。
- `bits`：所以有效数字是 53 位。

## 5. 验证 · 让计算机自己回答（18.7s）

- `l0`：在 Python 里，0.1 的真实值长这样。
- `l2`：两个近似值相加，得到 0.30000000000000004。
- `l4`：等号比较返回 False。
- `l5`：要比较，用 math.isclose。
- `note`：存进去的 0.1 已不是 0.1。

## 6. 尺度 · 误差有多大（10.0s）

- `n0`：53 位有效数字。
- `n1`：大约 16 位十进制。
- `n2`：和 0.3 只差 1 个 ulp。
- `eq`：误差是确定的，不是随机噪声。

## 7. 小结 · 三条规则（10.3s）

- `r0`：比较小数，别用等号。
- `r1`：金额用整数分。
- `r2`：要精确十进制，用 Decimal。
- `foot`：浮点适合计算，不适合账本。

## 8. 下期 · 留一个问题（8.6s）

- `q1`：它只是在用固定位数逼近无限。

## 旁白备注

- “0.30000000000000004”读作“零点三，后面十五个零，再一个四”（小数点后共 17 位：3 + 15 个 0 + 4）。
- `double` 统一读“双精度浮点数”，`ulp` 读字母 U-L-P。
- `math.isclose` 读“math 的 is close 函数”。
