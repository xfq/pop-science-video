# DIRECTION

## 一句话

- **观众**：对计算机好奇、但没有学过浮点数的观众；会写一点代码，也可能完全不写。
- **看完能复述的一句话**：浮点数用固定位数逼近实数，0.1 和 0.2 从存进去那一刻就被舍入，所以结果不是精确的 0.3。
- **为什么值得讲**：它每天都在发生，却常被当成“语言的 bug”；理解它能同时纠正一个误解，并给出可执行的三条写法。

## 理解路径

1. **观众现在以为**：0.1 + 0.2 当然等于 0.3；如果不等于，就是程序出错了。
2. **会卡住的地方**：为什么“看起来是 0.1”的值，在机器里不是 0.1；53 位到底花在哪。
3. **先给什么**：先给表达式和真实输出，制造认知冲突；再给一句结论“不是 bug，是二进制”；然后才拆机制。
4. **哪个类比能过桥**：一把刻度固定、但可以缩放的尺子。它对应“有限有效数字”，也能解释为什么误差的绝对大小随数量级变化。
5. **类比的边界**：尺子的刻度间距是固定的；浮点数的间距随指数变化。视频里用“末尾的 1 个单位（ulp）”把这一点说清。

## 三个候选角度

| 角度 | 钩子 | 视觉母题 | 风险 |
| --- | --- | --- | --- |
| A 日常 bug | “你被 0.1 + 0.2 骗过吗？” | 终端输出与红色报错 | 容易滑向“程序员吐槽”，机制讲不深 |
| B 数字的身份证 | “每个 double 都有 64 个格子” | 位条、内存转储 | 一开始就太抽象，非技术观众会掉队 |
| C 一把会缩放的尺 | “0.1 在这把尺上没有刻度” | 尺子 / 数轴 / ulp | 尺子画不好会变成装饰，必须和位字段对齐 |

**选定：A → C 的混合。** 先用 A 的日常冲突把观众拉进来，第二幕立刻转成 C 的“有限刻度”，再用 B 的位条作为证据。这样既不把片子做成开发者吐槽，也不从抽象格式开场。

理由：认知冲突必须在 3 秒内发生；但冲突之后要给一个可抓住的物理隐喻。位条负责“真的假的”，尺子负责“为什么”。

## 专属手法（因为概念有 X，所以画面用 Y）

1. **因为 0.1 的二进制展开是无限循环的 0011**，开场右侧放一条真正的 64 位内存转储，并让 0011 的节奏成为全片的视觉母题；不是通用的“科技粒子”。
2. **因为误差是确定性的、可定位的**，关键结论必须落在十六进制和 ulp 上：`0x1.999999999999ap-4`、`5.551115123125783e-17`。不用“精度损失”这种模糊词收尾。
3. **因为观众每天都在写十进制小数**，第一镜先给 `0.1 + 0.2` 和真实输出，再倒回去拆“存进去之前”发生了什么。
4. **因为“53 位”不是一个可感知的量**，位字段用真实比例画出 1 / 11 / 52，并用一条 64 位的实际位串验证；不画装饰性的“数据流”。
5. **因为这是一支解释片，不是产品片**，全片只有一个例子、一个结果、三条建议；不堆历史、不展开 IEEE 754 的所有舍入模式。

## 不做什么

- 不说“计算机算错了”或“Python 有 bug”——这是格式的默认行为。
- 不把 0.30000000000000004 说成随机噪声；它是确定性的舍入结果。
- 不说 Decimal 是无限精度；只说在足够精度下适合十进制账本。
- 不用“精度损失”四个字替代机制解释。
- 不展示未实际运行过的终端输出。
