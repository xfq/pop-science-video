# 案例：为什么 0.1 + 0.2 不等于 0.3

完整工程在 `examples/float-0-1-0-2/`，成片 `renders/final.mp4`。这个案例不是让你照着讲浮点数，而是示范“一个反直觉概念如何被拆到 98 秒”。

## 为什么选这个题

- **反直觉**：几乎所有人都以为答案是 0.3；真实输出是 0.30000000000000004。
- **可看见**：二进制展开、53 位、位字段、终端输出、ulp，都能画。
- **可带走**：三条写法（isclose / 整数分 / Decimal）能直接改代码。
- **可核验**：四语言实机输出一致；误差可以手算到 1 ulp。

受众：会写一点代码、但没学过浮点数的观众；不假设他们知道 IEEE 754。

一句话主张：**浮点数用固定位数逼近实数；0.1 和 0.2 从存进去那一刻就被舍入，所以结果不是精确的 0.3。**

## 方向

三个候选：

| 角度 | 钩子 | 视觉母题 | 风险 |
| --- | --- | --- | --- |
| A 日常 bug | “你被 0.1 + 0.2 骗过吗？” | 终端报错 | 容易变程序员吐槽 |
| B 数字身份证 | “每个 double 有 64 个格子” | 位条 | 开场太抽象 |
| C 会缩放的尺 | “0.1 在这把尺上没有刻度” | 尺/ulp | 容易变成装饰 |

选定 **A → C 的混合**：先用真实输出制造冲突，第二幕立刻转“有限刻度”，位条做证据。理由：冲突要在 3 秒内发生，但冲突之后必须给一个可抓住的物理隐喻。

专属手法：

1. 因为二进制展开是 0011 无限循环，开场右侧放真实 64 位转储；0011 的节奏成为母题。
2. 因为误差是确定性的，关键结论落在十六进制和 ulp 上，不用“精度损失”收尾。
3. 因为观众每天写十进制小数，第一镜先给表达式和真实输出，再倒回去拆机制。
4. 因为 53 位不可感知，位字段按真实 1/11/52 比例画，并用实际位串验证。
5. 因为这是解释片不是产品片，只用一个例子、一个结果、三条建议。

## 审片时改掉的东西

这些 bug 不是模板“应该没问题”的假设，而是实际踩到的：

1. **小数被字幕切断。** `split_caption` 把 `.` 当句号，`0.30000000000000004` 被切成 `0.` 和 `30000000000000004`。改成只按中文标点和 `!?;` 切，保留小数。
2. **所有场景只有 hook 有画面。** `build.mjs` 把 `timeline.json` 的绝对 mark 时间直接写进 sub-comp；sub-comp 的 timeline 是镜头本地时间，14s 的 mark 在 8s 的镜头里永远等不到。改成 `mark - scene.start`。
3. **切点黑屏。** 每个镜头之间留了 0.45s 的 `sceneGap`，加上 intro 从 opacity 0 开始，切点会黑 0.45–1.0s。改成 `sceneGap: 0.02`，intro 保持可见只做位移。
4. **页脚和字幕重叠。** 页脚在 116px、字幕在 48px，同一行。页脚抬到 154px。
5. **对比度不足。** 深色底上的 `--faint` 小字只有 3.7–4.4:1；提亮到 `#7d8fa8`，位段文字改浅色，数字卡序号改 `--muted`。
6. **hook 13 秒几乎静止。** 首帧必须完整，所以不能把结果藏起来；改成“结果/公式/下划线”在 mark 处做脉冲/生长，保留首帧完整。
7. **TTS 实际时长比预估长。** 初版 548 字 → 104s 语音 → 124s 成片；把台词压到 475 字、语速 190，落到约 100.5s。**先写台词再定时长**。

## 可复用的经验

- **先给结果，再拆机制。** 反直觉的题，第 1 帧就是结论；但结论之后必须马上给“为什么”，否则只是标题党。
- **一个数字只出现一次。** 0.30000000000000004 在 hook、code、numbers 各出现一次，每次承担不同任务（冲突/证据/量级），不是复读。
- **真实输出比解释更有说服力。** 终端里的 `False` 和 `True` 比“浮点数比较不可靠”有力。
- **自动检查通过 ≠ 可以发布。** 这版仍需真人试听/试看；TTS 是 Tingting，不是真人。
- **模板不是风格包。** 这套深色实验室风格可以复用，但每个新题要重新回答“因为概念有 X，所以画面用 Y”；不要把 0011 母题搬到 DNS 或 GC。
