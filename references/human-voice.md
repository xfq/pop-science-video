# 真人旁白

## 为什么 TTS 会“机器感”

TTS 的问题通常不在音色，而在**韵律**：

- 每个字的时长太均匀，重音落不到动词和对比词上；
- 句子之间的停顿一样长，没有“想一下”的感觉；
- 没有呼吸、口腔噪声和轻微的语气词；
- 数字、英文缩写、代码标识符的读法常常不对；
- 长句的语调平，观众听不出哪一句是结论。

对 90 秒的科普片，最有效的修复不是换一个更贵的 TTS，而是**换成真人录音**。33 句、每句 2–5 秒，认真录大约 30–45 分钟；这是整支片子里回报最高的一步。

## 三条路线

| 路线 | 适合 | 代价 | 备注 |
| --- | --- | --- | --- |
| A. 真人录音（推荐） | 正式发布、需要可信度 | 30–45 分钟 + 一只麦克风 | 手机自带麦克风就够 |
| B. 外部高质量 TTS | 没有录音条件、更新频繁 | 需要账号/费用；仍是 AI 音 | ElevenLabs / Azure / HeyGen 等，逐句导出后导入 |
| C. 本机 TTS 换音色 | 草稿、内部预览 | 仍然有机器感 | 用 `audition_voices.py` 试听，不要当正式片 |

真人录音的流程和 TTS 完全兼容：最终都落到 `assets/tts/manifest.json`，后面的时间轴、字幕、混音、渲染不变。

## 录音前的准备

### 房间

- 小房间、软装多（窗帘、床、沙发、地毯）比大客厅好。
- 避开空调、冰箱、电脑风扇、窗外车流；录 10 秒“房间底噪”听一下。
- 不要在空房间里对着墙录；回声会让声音“远”。
- 手机录音也可以：把手机放在软垫上，不要手持。

### 麦克风

- 手机自带麦克风或普通 USB 麦即可；不必先买昂贵设备。
- 麦克风离嘴 **15–20 cm**，稍微偏 15–30°，避免喷麦（p/b/f）。
- 不要用手捂住手机底部麦克风；不要用蓝牙耳机录（延迟/压缩）。
- 如果用领夹麦，固定在胸口上方，避免衣服摩擦。

### 电平

- 录最响的一句，峰值控制在 **−12 到 −6 dBFS**，不要削顶。
- 不要开手机的“降噪/美音/混响”；保留干声。
- 采样率 44.1/48 kHz 都行；导入时会统一到 48 kHz 单声道。

## 怎么读

- **对一个人说**，不要“播音”。想象你在给同事解释一个他刚问的问题。
- 每句开头稍微提气，结论词（“不是”“因为”“所以”“只差”）加重。
- 数字放慢：`0.30000000000000004` 读“零点三，后面十五个零，再一个四”，不要赶。
- 英文术语按字母/常见读法：`IEEE 754` → “I triple E 754”；`ulp` → “U L P”；`math.isclose` → “math 的 is close”。
- 句号处停 0.3–0.5 秒；逗号处停 0.15–0.25 秒。不要在每个词之间停顿。
- 读错就**整句重来**，不要剪中间；一句一个文件，后期最省事。
- 每句前后留 0.5 秒安静，方便 trim。
- 先录 2–3 句试听；确认语速、距离、底噪，再录全片。

### 表演小技巧

- 站着录，气息更稳；坐着就把背挺直。
- 微笑会让声音更暖，但不要笑出声。
- 说到“这不是 bug”时真的带一点“别急”的语气；说到“53 位”时放慢。
- 不要模仿纪录片腔；科普的说服力来自“你真的懂”，不是“你很庄重”。

## 录制工作流

### 1. 导出录音稿

```sh
python3 <SKILL>/scripts/make_recording_kit.py --project <FILM>
```

生成：

```text
recording/
  NARRATION.md      # 按场景分组，逐句文件名/目标时长/读法/字幕
  lines.csv         # 表格/提词器
  lines.json        # 机器可读
  takes/            # 把录音放这里
  guide/            # 可选：当前 TTS 参考音（--guide）
```

文件名必须和稿子一致：`hook-000.wav`、`pivot-002.wav`。也接受 `01-hook-000`、`hook_000`、`.m4a`、`.mp3`、`.aiff`。

### 2. 录

按 `NARRATION.md` 逐句录。每句一个文件，前后留 0.5 秒。先录前 3 句试听；有问题先修房间/距离/电平，不要录完 33 句再返工。

### 3. 导入

```sh
python3 <SKILL>/scripts/import_recordings.py --project <FILM>
```

它会：

- 找 `recording/takes/` 里的文件，按文件名映射到台词；
- 统一转成 48 kHz 单声道 16-bit WAV；
- 去掉首尾静音（默认 −50 dB）、70 Hz 高通、峰值归一到 −3 dBFS；
- 量出每句真实时长，写 `assets/tts/manifest.json`（`provider: human`）；
- 生成 `recording/import-report.json`，标出过短/过长/削顶/缺句；
- 缺句默认报错，不会悄悄用 TTS 补。

常用参数：

```sh
--force                 # 重新处理所有 take
--allow-missing         # 缺的句子保留旧 TTS（不推荐，声音会跳）
--denoise               # 轻降噪，可能让声音发闷，先试一句
--no-normalize          # 保留原始电平
--highpass 80           # 男声/房间轰鸣时可调高
--target-peak -3        # 每句峰值目标
```

### 4. 重排时间轴、混音、渲染

```sh
python3 <SKILL>/scripts/make_timeline.py --project <FILM>
python3 <SKILL>/scripts/mix_audio.py --project <FILM>
cd <FILM>
node build.mjs
npx --yes hyperframes@0.8.184 check
npx --yes hyperframes@0.8.184 render --quality delivery --output renders/final.mp4
```

时间轴会按真实语速重排，**不要手动改字幕时间**。如果某句比目标长很多，先改台词/重录，不要用 1.5× 变速硬压。

## 处理原则

- **轻处理**：trim + 高通 + 峰值归一就够了。不要用重压缩、混响、AI 降噪把声音做“干净”，那会更快变成机器感。
- **保留呼吸**：句首/句尾的轻微呼吸是自然感的一部分；trim 阈值 −50 dB 已经足够温和。
- **不要每句单独 EQ**：同一支片子用同一套设置，否则声音会忽亮忽闷。
- **削顶不可逆**：录的时候就控制电平；削顶的句子必须重录。
- **噪声大就重录**：`--denoise` 只能救轻微底噪；空调声/交通声救不回来。
- **齿音/喷麦**：先改麦克风角度和距离；必要时轻 de-ess，不要全局压高频。

## 和音乐、字幕的配合

- 人声动态比 TTS 大；`mix_audio.py` 仍会把整体压到 −16 LUFS，但会让位更深一点。听一下 `--duck-db 11` 是否更舒服。
- 真实语速可能让某些镜头变长/变短；视觉有 tail，通常能吸收。超出 20% 就考虑删词，而不是加速。
- 字幕按新时间轴自动重排；检查小数/英文术语没有被切断。
- 最后 0.5 秒留白，不要把最后一个字切掉。

## 暂时只想去掉机器音？

如果还没有录好，但不想让 TTS 出现在预览/内部版里，可以先出“音乐 + 字幕”版：

```sh
python3 <SKILL>/scripts/mix_audio.py --project <FILM> --mute-voice
cd <FILM>
node build.mjs
npx --yes hyperframes@0.8.184 render --quality delivery --output renders/final.mp4
```

`--mute-voice` 保留时间轴、字幕、配乐和音效，只把旁白静音；它不是正式片的替代品（观众要靠字幕读完全片），但可以先去掉机器音，等录音到位再重新混。`check_delivery.py` 仍会检查音乐/音轨，不会把静音轨当成“有人声”。

## 只替换部分句子？

不推荐。人声和 TTS 的音色、底噪、距离感不同，观众会立刻听出来。要么全录，要么全用同一条 TTS 路线；如果必须混，`--allow-missing` 可以保留旧句，但要在交付说明里写清“部分 AI 补录”。

## 外部 TTS

如果只能用 AI 声音，选一个支持**逐句导出**的服务（ElevenLabs / Azure / HeyGen 等）：

1. 用 `NARRATION.md` 的“读法”逐句生成；
2. 导出 WAV/MP3，按 `hook-000.wav` 命名；
3. 放进 `recording/takes/`，跑 `import_recordings.py`（它不关心文件是真人还是 AI）；
4. 在交付说明里写“AI 配音，provider/voice”，不要伪装真人。

## 本机音色试听

没有录音条件、又想比 Tingting 自然一点：

```sh
python3 <SKILL>/scripts/audition_voices.py --project <FILM>
```

会在 `recording/auditions/` 生成同一句在多个 macOS 中文音色下的 WAV，方便你挑一个。它仍然是 TTS；正式片优先真人。

## 验收清单

- [ ] 33 句都有文件，文件名匹配，没有缺句。
- [ ] 每句峰值 ≤ −3 dBFS，没有削顶。
- [ ] 没有空调/交通/键盘声；底噪听不见。
- [ ] 数字、英文、版本号读对。
- [ ] 句尾没有被切；句间停顿自然。
- [ ] 手机外放能听清每个字。
- [ ] 时间轴总长在目标 ±15% 内；超了就删词/重录。
- [ ] `mix.wav` 重新生成，`build.mjs` 重新跑，MP4 重新渲染。
- [ ] 交付说明写清真人/AI、麦克风、是否试听。
