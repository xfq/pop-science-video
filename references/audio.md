# 声音

声音不是画面的背景，而是“谁在说、什么时候该注意”的提示。旁白优先真人；TTS 的机器感通常来自韵律，不是音色，换音色只能缓解。完整录音流程见 [真人旁白](human-voice.md)。科普片的声音优先级：**旁白清楚 > 关键动作听得见 > 音乐不烦人 > 音效不抢戏。**

## 音乐

### 先选情绪，再选音色

| 概念气质 | 情绪 | 速度 | 音色 | 避免 |
| --- | --- | --- | --- | --- |
| 反直觉、好奇 | curious | 88–96 BPM | 电钢琴/马林巴/轻脉冲 | 大型弦乐、史诗鼓 |
| 机制、冷静 | focused | 80–88 BPM | 低音 pad、稀疏 pluck | 强旋律、人声 |
| 轻快、生活化 | playful | 100–112 BPM | 短 pluck、木块、shaker | 卡通音效 |
| 风险、故障 | tense | 96–104 BPM | 低频 drone、窄脉冲 | 恐怖片 stinger |

本 skill 的 `music.py` 用 numpy 合成四种情绪，92 BPM 为默认。它不是“生成一首歌”，而是写一段**不抢旁白的 bed**：四小节循环、无强旋律、留中频给语音。

### 来源顺序

1. 用户提供的音乐（确认授权）。
2. 本机真的能跑的音乐生成模型（记录模型/版本/提示词）。
3. 代码合成（本 skill 默认；保留源码和 seed，可复现）。
4. 素材库（记录来源、许可、是否需署名）。

不要用来路不明的“免版权”音乐。素材库的“免费”通常有条件。

### 编曲与镜头

- 按镜头边界排段落：hook 用稀疏 intro，机制段加入脉冲，recap 收掉鼓，outro 留 pad。
- 不要在每一镜都加“ riser”；只在真正需要抬升的转场用。
- 音乐在旁白出现时要让位；不要在说话时加响亮的高频 pluck。
- 结尾留 1–2 秒淡出，不要硬切。

## 音效

内置 8 个原创 WAV（`assets/sfx/`），由 `make_sfx.py` 生成：

| 文件 | 用途 | 不该用在哪 |
| --- | --- | --- |
| `tick.wav` | 小步骤、光标、计数 | 每个字都加 |
| `pop.wav` | 元素出现、标签 | 连续弹出 |
| `whoosh.wav` | 场景转场、尺度变化 | 每个镜头都加 |
| `chime.wav` | 正确、完成、通过 | 反例/错误 |
| `error.wav` | 错误、False、失败 | 只是“有难度”的内容 |
| `typing.wav` | 终端输入 | 真实键盘录音更自然时 |
| `riser.wav` | 结论前的抬升 | 每 10 秒一次 |
| `stamp.wav` | 结论落地、印章 | 轻柔的过渡 |

规则：

- 音效服务动作：元素出现、代码运行、错误发生、结论落地。
- 一个镜头最多 1–2 个音效；转场 whoosh 已经很够。
- 音效峰值对齐动作的**视觉起始**，不是动作结束；`mix_audio.py` 会把 cue 放在句子起点。
- 音效音量低于旁白 10–15 dB；不要用音效盖住辅音。

## 混音

默认链路（`mix_audio.py`）：

```text
逐句旁白（已去首尾静音）
  → 放到 timeline 的 chunk.start
  → 整体峰值归一到 -3 dBFS
配乐
  → -17 dB 相对增益
  → 按旁白包络做 9 dB 让位（attack 快、release 慢、带 40ms 预滚）
音效
  → -12 dB 相对增益；转场 -4 dB
  → 求和
  → 峰值保护
  → loudnorm 两遍到 -16 LUFS / -1.5 dBTP
```

参数不是死的：

- 旁白很轻/很响时，先修 TTS/录音，不要只靠压缩。
- 音乐本身很满时，把 `--music-db` 降到 -20 或换更稀疏的编曲。
- 关键结论想更“落地”，把 `--duck-db` 加到 11–12；不要超过 15，否则音乐像断掉。
- 目标响度按平台：YouTube/B 站约 -14 到 -16 LUFS；播客可到 -16；不要为了“响”把真峰值推过 -1 dBTP。

### 让位（ducking）

让位不是“把音乐整体调小”，而是**说话时降、停顿处回来**。`mix_audio.py` 用旁白包络（10ms 块 + 快 attack/慢 release）控制音乐增益；旁白停止后 200–400ms 恢复。预滚 40ms 保证第一个音节出现时音乐已经让开。

### 试听清单

- [ ] 手机外放：每个字都清楚吗？辅音（s/sh/f）有没有被音乐盖住？
- [ ] 耳机：音乐有没有刺耳的高频？低频有没有糊住人声？
- [ ] 停顿处：音乐回来得自然吗？有没有“抽气”感？
- [ ] 转场：whoosh 和画面切点对齐吗？有没有迟到/早到？
- [ ] 结尾：音乐淡出是否完整？有没有被硬切？
- [ ] 整体：连续看 1 分钟，会不会觉得吵/累？
- [ ] 响度：`check_delivery.py` 的 LUFS/true peak 是否在范围内？

没有实际试听，就不要在交付里写“声音已验收”。自动检查只测响度和文件，不测听感。

## 命令

```sh
python3 scripts/music.py --project <FILM> --mood curious --bpm 92 --seed 7418
python3 scripts/mix_audio.py --project <FILM> --duck-db 9 --target-lufs -16
python3 scripts/check_delivery.py --project <FILM>
```

`music.py` 的输出在 `evidence/music.json`；`mix_audio.py` 的输出在 `evidence/audio-mix.json`，记录旁白段数、音乐增益、让位、音效 cue、实测 LUFS/true peak。交付时把这两份一起给，方便复现和修改。

## 常见问题

| 症状 | 原因 | 改法 |
| --- | --- | --- |
| 音乐盖住人声 | 音乐太满/中频冲突 | 降 3–6 dB，换稀疏编曲，或加宽让位 |
| 人声忽大忽小 | 逐句 TTS 音量不一致 | 先按句归一化，再整体归一；不要只加压缩 |
| 转场音效迟到 | cue 放在画面切点而不是动作起点 | 提前 80–120ms；对齐视觉起始 |
| 结尾突然 | 音乐没有淡出/视频被截 | 末尾留 1–2s，检查 `data-duration` |
| 听起来“像 AI” | TTS 句读/重音不自然 | 改写短句、加停顿、换音色；正式片优先真人 |
