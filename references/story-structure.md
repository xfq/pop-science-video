# 叙事结构

科普片不是“把文档念一遍”，而是带观众走完一次理解。结构的目标只有一个：**让观众在 90 秒内自己说出“哦，原来是因为这个”。**

## 一条主线

写片前先填这五行：

```text
观众现在以为：0.1 + 0.2 当然等于 0.3，不相等就是 bug。
卡点：      他们不知道 0.1 存进去时已经被舍入。
先给：      先给真实输出，制造冲突；再给“不是 bug，是二进制”。
类比：      一把刻度固定、但可以缩放的尺子。
边界：      尺子的刻度间距固定；浮点的间距随指数变化，所以用 ulp 收尾。
```

五行写不出来，说明还没想清；不要用动画掩盖。

## 90 秒标准结构

| 段落 | 时长 | 任务 | 画面 | 常见错误 |
| --- | --- | --- | --- | --- |
| 钩子 | 0–12s | 给反直觉的结果，建立“这和我有关” | 大表达式 + 真实输出 + 一个记忆点 | 开场白、频道介绍、先讲历史 |
| 转折 | 12–22s | 给一句结论，把“bug”改成“机制” | 一句大字 + 一个关键词 | 结论太抽象，观众不知道在解释什么 |
| 机制 | 22–50s | 拆 3–5 步，每步一个因果 | 流程 / 位字段 / 层次 / 时间线 | 一次塞 8 步；每步都靠旁白硬讲 |
| 证据 | 50–70s | 用真实代码、数据或对照证明 | 终端 / 数字卡 / 对照卡 | 伪造输出；数字没有单位 |
| 收束 | 70–85s | 给可执行的三条 / 一个判断 | 清单 / 规则 / 代码片段 | 只喊口号，没有动作 |
| 回扣 | 85–90s | 回到开头的问题，留一个下一问 | 大字问题 + 来源 | 突然结束；或硬加“点赞关注” |

不是每支片都必须六段齐全。60 秒版可以合并“证据”和“收束”；3 分钟版可以把“机制”拆成两章。

## 60 秒版

```text
0–5s    反直觉结果
5–12s   一句结论（不是 X，是 Y）
12–38s  机制三步（每步 6–9 秒）
38–48s  一个证据/对照
48–55s  一句可执行建议
55–60s  回扣 + 下期
```

只讲一个机制，只给一个例子。任何“顺便说一下”的内容都删。

## 3–6 分钟版

按“章”组织，每章 40–70 秒，章末用一句大字收束，再进下一章：

1. **钩子 + 承诺**（15–25s）：给结果，告诉观众这支片会回答哪三个问题。
2. **第一章：它是什么**（40–60s）：建立最小模型，给第一个例子。
3. **第二章：为什么会这样**（60–90s）：拆机制，给真实证据。
4. **第三章：代价 / 权衡 / 误区**（60–90s）：边界、反例、常见错误。
5. **收束：带走什么**（20–30s）：三条规则或一个判断框架。
6. **回扣 + 下一问**（10–20s）。

长片更需要“每 30 秒一个视觉变化”：不是换壁纸，而是换信息形态（图 → 代码 → 对照 → 数字）。

## 钩子的六种写法

1. **真实输出**：把终端/浏览器/账单上的结果直接放出来。
2. **反常识数字**：“一个汉字在 UTF-8 里最多占 4 个字节，但你的数据库可能只给了 1 个。”
3. **代价**：“这个默认值，让一笔 0.01 元的账对不上。”
4. **对照**：“同一段代码，在 Python 和 C 里打印出不同的数。”
5. **问题链**：“如果 0.1 不是 0.1，那它是什么？如果它不是 0.1，为什么打印出来是 0.1？”
6. **现场演示**：真的跑一遍，让观众看到结果；不要只说“我们来看一个例子”。

钩子之后 2 秒内要给“承诺”：这支片会解释什么、不会解释什么。承诺越具体，观众越愿意跟。

## 机制段：因果链，不是步骤清单

每一步都写成“因为 A，所以 B”，而不是“第一步、第二步、第三步”。

```text
因为十进制 0.1 写成二进制是无限循环的 0011，
所以它不能被有限位数的尾数精确表示；
因为 binary64 只留 53 位有效数字，
所以存进去的 0.1 已经是最近的可表示值；
因为两个近似值相加后还要再舍入一次，
所以结果落在 0.3 旁边那个可表示的数上。
```

画面上的每一步只推进一个“因为”。如果一步里有两个因果，拆成两步。

## 类比：先过桥，再拆桥

类比段只做三件事：

1. **给桥**：用一个观众熟悉的东西，把机制的第一层直觉搭起来。
2. **指边界**：明确说“这个类比在哪里不成立”。
3. **回真实**：用真实术语/数字收尾，不要让类比成为结论。

例：

> 你可以把它想成一把刻度固定的小数尺：53 个格子，写不下的部分只能舍入。但这把尺的刻度会随指数缩放，所以它不是一个固定的小数点——最后我们用 ulp 来量这一点点差。

类比不要超过 20 秒；超过就会变成另一个需要解释的东西。

## 证据段：让观众自己验证

证据不是“我说了算”，而是“你也可以试”：

- 终端里跑真实代码，保留提示符和输出；
- 给一条可复制的命令/表达式；
- 给对照：两种语言、两个版本、两种写法；
- 给数字：单位、口径、版本、测量方法。

如果证据需要 30 秒才能看懂，说明它不适合放在 90 秒片里；换成更小的证据，或删掉。

## 收束：给动作，不给口号

差的收束：“所以我们要重视基础。”
好的收束：“比较小数用 `math.isclose`；金额用整数分；要精确十进制用 `Decimal`。”

三条以内；每条都能在明天用上。最后一句回到开头的问题，形成一个闭环。

## 转场与节奏

- **硬切**是默认。上一镜的结论说完就切，不需要每个转场都擦除/缩放。
- 转场只在“时间/空间/尺度”变化时使用：从十进制到二进制、从代码到内存、从 0.1 到 64 位。
- 每 20–30 秒至少换一次信息形态；不要连续三镜都是“大字 + 旁白”。
- 镜头时长跟着语音走：一句话一个镜头，或两句话一个镜头；不要为了卡点把一句话切成两半。
- 留白是节奏的一部分：结论说完后停 0.4–0.6 秒，比再加一句解释更有用。

## 理解测试

写完后，找一个人（或自己隔一小时）按 1× 速度看一遍，不暂停，然后问：

1. 这支片在回答什么问题？
2. 机制的第一步是什么？最后一步是什么？
3. 哪个类比？它在哪一步不成立？
4. 看完你会改哪个写法/判断？
5. 哪一镜你走神了？为什么？

第 5 题的答案通常就是需要删/改的镜头。**能复述 ≠ 能背诵术语**；如果对方只记住“浮点数不准”，说明机制没讲清。

## 常见失败模式

| 症状 | 原因 | 改法 |
| --- | --- | --- |
| 前 10 秒很空 | 先讲背景/历史 | 把结果提到第 1 帧 |
| 中段像念文档 | 只有步骤，没有因果 | 每步改写成“因为…所以…” |
| 画面很炫但记不住 | 视觉手法和概念无关 | 每个手法写一条“因为概念有 X” |
| 信息过载 | 一镜多个主张 | 一镜只留一个主张，其他移到下一镜 |
| 结尾无力 | 没有可执行动作 | 给三条规则/一个判断，回扣开头 |
| 时长超了 | 台词太满/例子太多 | 先删例子，再删解释，最后才加速配音 |
