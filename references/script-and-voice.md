# 台词与配音

科普片的台词是“解释”，不是“朗诵”。一句话只做一件事：给结论、给因果、给证据、给动作。

> 正式片优先真人录音；TTS 只做草稿或没有录音条件时的方案。录音稿、设备、导入和验收见 [真人旁白](human-voice.md)。

## 中文口播的基本盘

- **短句。** 一句话一个意思，尽量不超过 25 个汉字；长句拆成两句，让配音有换气。
- **先因后果。** “因为 A，所以 B”比“B 的原因是 A”更容易跟。
- **少用“我们”。** “我们来看”会拖节奏；直接说“看这个输出”。
- **术语第一次出现时给一句人话。** “尾数，也就是有效数字那一段。”
- **不念符号。** 不说“大于号”“双等号”，说“等号比较”“大于”。
- **口语连接。** “所以”“也就是说”“问题是”可以保留；不要写“综上所述”“众所周知”。

### 语速与字数

| 语言 | 舒适语速 | 90 秒台词量 | 备注 |
| --- | --- | --- | --- |
| 中文 | 3.5–5.5 字/秒 | 350–480 字 | 含标点；TTS 可能更慢 |
| 英文 | 130–160 词/分钟 | 220–280 词 | 技术词多时取低值 |

先写台词，再用 TTS 实测。不要先定 90 秒然后硬塞 600 字。

`check_content.py` 的“字/秒”按字符数 ÷ 语音秒数计算；英文术语、版本号、代码标识符会把它抬高。看到 6–8 字/秒的警告，先回放那两句：如果听感不赶，可以保留，并在审片记录里说明是拉丁字符导致的估算偏差。

## 一句话的结构

```text
[连接词] + [主语] + [动作/变化] + [结果] + [限定]
```

例：

- “因为尾数只有 53 位，所以存进去的 0.1 已经是一个近似值。”
- “两个近似值相加，再舍入一次，结果就落在 0.3 旁边。”
- “要比较小数，别用等号；用 math.isclose。”

避免：

- “众所周知，浮点数存在精度问题。”（没有信息）
- “这是由于二进制无法精确表示十进制小数所导致的。”（太长、太书面）
- “我们可以看到这里有一个非常有意思的现象。”（废话）

## 术语首次出现

每个术语至少给三件事中的两件：**中文解释、英文原名、一个具体例子。**

| 术语 | 首次出现可以这样说 |
| --- | --- |
| binary64 | “双精度浮点数，也就是 binary64。” |
| 尾数 / significand | “尾数，也就是有效数字那一段。” |
| ulp | “ulp，最后一位的 1 个单位。” |
| IEEE 754 | “IEEE 754，浮点数的国际标准。” |
| 舍入 | “舍入，把结果放到最近的可表示值上。” |

不要在第一次出现时给完整定义；给“够用的解释”，后面再补。

## 数字、单位与读音

字幕和配音分开写：

```json
{
  "caption": "结果是 0.30000000000000004。",
  "tts": "结果是零点三，后面十五个零，再一个四。"
}
```

规则：

- 字幕保留阿拉伯数字、单位符号；配音写中文读法。
- 大数/小数按中文习惯读；“0.1”读“零点一”，不读“点一”。
- 英文缩写按字母读：`ulp` → “U L P”；`IEEE` → “I triple E”；`CPU` → “C P U”。
- 版本号/型号：`Python 3.14` → “Python 三点一四”；`RTX 4090` → “R T X 四零九零”。
- 百分号/单位：`5 ms` → “五毫秒”；`1 GB` → “一 GB”或“一吉字节”，全片统一。
- 公式：先说人话，再给符号；“a 加 b”不必读成“a plus b”。

本片的一个具体读法：`0.30000000000000004` 小数点后是 `3 + 15 个 0 + 4`，所以读“零点三，后面十五个零，再一个四”。如果不确定，写进 `tts` 字段，不要让 TTS 自由发挥。

## 术语词典

在 `film.json` 的 `meta.voice.lexicon` 里做全局替换：

```json
{"IEEE 754": "I triple E 754", "double": "双精度浮点数", "ulp": "U L P"}
```

注意：

- 替换只作用于 `tts`，不影响字幕。
- 按最长 key 优先替换，避免 “754” 先于 “IEEE 754” 被替换。
- 不要把中文词替换成英文；词典是给发音用的。
- 逐句 `tts` 字段优先级最高；特殊读法直接写在那句里。

## 字幕

- 一句一条；按 `，。！？；` 切分，逗号也可以切成两条短字幕。
- 单条 ≤ 26–30 个汉字；最多两行。模板的 `split_caption` 会在标点处切，并合并过短片段。
- **不要在小数点处切。** `0.30000000000000004` 必须保持完整；`split_caption` 已排除 `.` 和 `,`。
- 数字、代码、专有名词原样保留；不要在字幕里写 TTS 读法。
- 字幕底部居中，深色胶囊；不要挡住页脚来源。模板把页脚抬到 154px，字幕在 48px。
- 字幕时间和语音对齐；一条字幕最短 0.7 秒，太短会闪。

## 配音选择

| 方案 | 适合 | 注意 |
| --- | --- | --- |
| 真人录音 | 正式片首选 | 需要安静环境、统一麦克风/语速；保留干声 |
| edge-tts | 没有录音条件、需要自然中文 | 网络依赖；可能被限流/失效；必须试听 |
| macOS `say` | 本地草稿/离线 | 音色机械；`Tingting` 等中文音色可用；正式片注明 |
| 自备录音文件 | 有配音/自己录 | 命名 `<scene>-<NNN>.wav`，48kHz 单声道，逐句 |

`tts.py` 的 `auto` 会先试 edge，失败后在 macOS 回退 `say`。正式交付如果用了 TTS，写清楚用的是哪个 provider/voice，不要让观众以为是真人。

### 试听清单

- [ ] 前 3 句的术语读音对不对？
- [ ] 数字/小数/版本号读对了吗？
- [ ] 句尾有没有被截断？句间停顿是否自然？
- [ ] 语速是否跟得上画面？有没有一句字幕没读完就切？
- [ ] 有没有机械重音/奇怪停顿？需要改写句子还是换音色？
- [ ] 手机外放能听清吗？（不要只戴耳机试）

## 台词与画面的对齐

每句旁白在 `film.json` 里写一个 `mark`：

```json
{"caption": "一个 double 只留 53 位。", "tts": "一个双精度浮点数，只留五十三位。", "mark": "s1"}
```

- `mark` 放在这句话**开始**的时刻；画面元素用 `data-reveal="s1"` 接住。
- 一句话只标一个 mark；需要同时揭示两个元素时，给两个元素同一个 mark（模板会按顺序 stagger）。
- mark 名用小写 ASCII：`s0`、`result`、`note`、`l2`；不要用中文/空格。
- 没有 mark 的句子只推进字幕；不要让画面一直不动。
- 如果画面元素在 build 时找不到 mark，构建会警告并把它放在 0.25s；正式片要把警告清零。

## 改写练习

原句：“浮点数由于采用二进制表示，无法精确表示某些十进制小数，因此会产生精度误差。”

改写：“0.1 写成二进制，是 0011 的无限循环。只留 53 位，就只能舍入。”

改写原则：**删掉“由于/因此/从而”，改成两个具体动作；把抽象名词换成可看见的东西。**
